# labs/linux: practice files for Part 1 (Days 3 to 7)

Small, realistic and completely fake files for the Linux command line lessons.
Every example in Part 1 runs on these files, so your output should match the lessons
(apart from dates, times, owners and process IDs).

Nothing here is real: the IP addresses come from the ranges reserved for documentation
(192.0.2.x, 198.51.100.x, 203.0.113.x), the domains are `example.com`, and the "secrets"
in `server/etc/shop/.env` are placeholders.

## What is in the folder

| Path | What it is | Used on |
|---|---|---|
| `app.log` | 37 lines from a checkout service: INFO, WARN and ERROR lines with request IDs (`req=7f3a9c`), one Java stack trace | Days 4, 5, 7 |
| `logs/` | Logs from four services that all saw request `7f3a9c`, plus `archive/` with yesterday's log | Days 4, 5, 7 |
| `access.log` | 238 requests in nginx "combined" format: IP, time, request, status, bytes, referrer, user agent | Days 4, 5 |
| `events.jsonl` | 18 JSON events, one per line, for jq | Day 5 |
| `pods.json` | A trimmed list shaped like `kubectl get pods -o json` output | Day 5 |
| `server/` | A pretend server: `etc`, `home`, `opt`, `tmp`, `var/log`, `var/backups`, with a few large files (1 to 3 MB) for `find` and `du` | Days 3, 4, 6 |
| `start-lab.sh` | Starts the practice container and installs the extra tools | Day 3 on |

## Get the folder onto your Mac

Clone the course repo once, then copy this folder to its own place:

```bash
git clone --depth 1 https://github.com/arunav-bhattacharya/devops-from-zero ~/code/devops-from-zero
cp -R ~/code/devops-from-zero/labs/linux ~/code/linux-lab
```

## Open a Linux shell with the files inside

You need Docker Desktop running (Day 2). In a Mac terminal:

```bash
cd ~/code/linux-lab
docker run -it --rm -v "$PWD":/work -w /work ubuntu:24.04 bash
```

- `-it` gives you an interactive terminal, and `--rm` deletes the container when you `exit`.
- `-v "$PWD":/work` shows this folder inside the container as `/work`. Files you change there
  are your real Mac files, so they survive `--rm`.
- `-w /work` starts you in that folder.

The Ubuntu image is minimal. Inside the container, install the tools the lessons use
(about 20 seconds):

```bash
apt-get update && apt-get install -y less tree jq file curl lsof iproute2 psmisc shellcheck
```

`bash start-lab.sh` does both steps in one go.

Tools you install inside the container disappear with it. If you would rather keep them between
sittings, start a named container without `--rm` once, and come back to it later:

```bash
docker run -it --name linux-lab -v "$PWD":/work -w /work ubuntu:24.04 bash   # first time
docker start -ai linux-lab                                                    # every time after
```

On Linux or Windows (WSL2) the same `docker run` command works from a terminal in this folder.

## Days 6 and 7: a small Ubuntu VM

systemd (services, `systemctl`, `journalctl`) does not run in a plain container, and SSH is more
realistic with a real machine. Day 6 creates a virtual machine with Multipass
(installer: https://canonical.com/multipass/install, macOS 14 or later):

```bash
multipass launch 24.04 --name devbox
multipass shell devbox
```

Delete it when you finish Part 1 with `multipass delete devbox` (older Multipass versions also
need `multipass purge`).

## Resetting the files

Some exercises change files on purpose: Day 4 gives some logs old dates with `touch -d` and
deletes `server/tmp/upload-3f9a.part`. To start fresh, delete `~/code/linux-lab` and copy the
folder again.
