# Reconcile, Pin, Verify: Learning DevOps in 2026

The fastest way for a Kotlin/JVM engineer to build real DevOps intuition in October 2026 is to take the fourteen topics in the order a change travels (shell, network and cloud, container, pipeline, build, infrastructure, cluster, GitOps, observability, security and platform) and to treat almost every tool as one of two ideas. The first is **a loop that pushes reality toward a declared desired state**: Terraform's plan, Kubernetes controllers, Argo CD. The second is **a content-addressed artifact that you can only trust once it is pinned by digest and verified**: image digests, SHA-pinned actions, the Gradle wrapper checksum, cosign signatures. All of it can be practised free on an Apple Silicon Mac with Docker Desktop, kind, a Multipass VM and public GitHub repos. The two exceptions still have no-bill entry points: Dynatrace offers a public Playground and a 15-day trial, and each of the three big clouds has a credit plan that cannot charge your card while you stay on it (AWS closes the account, Azure disables services, Google waits for you to activate billing). For a learner, the bigger hazard is stale material, not difficulty. Since 2025 ingress-nginx has been retired, Helm 4 has replaced Helm 3, Kyverno has deprecated `ClusterPolicy`, Grafana has frozen its `grafana-oss` image, the OpenTelemetry Collector has renamed its OTLP exporters, Jaeger v1 has reached end of life, Terraform has deprecated DynamoDB locking, Gradle 9 has removed long-standing APIs, and GitHub has started blocking fork checkouts under `pull_request_target`. Many popular videos therefore teach commands that now fail. Beginner mistakes fall into three families that recur in every tool. The first is missing a hidden transformation step: shell expansion, Gradle's configuration phase, Terraform state, PromQL's rate-then-sum. The second is trusting mutable names such as `:latest`, `@v4` and Git tags. The third is treating a one-time action as an ongoing control, for example scanning once, signing without verifying, or deleting a leaked secret instead of rotating it. The sections below cover each topic in turn: the order to learn the concepts in, the facts that are current today, the classic mistakes, the best free lab, and the references worth your time.

## Two mental models and one laptop carry all fourteen topics

The idea that ties the course together is the **reconciliation loop**. The Kubernetes docs explain a controller with a thermostat: you set the desired temperature, the room has a current temperature, and the controller acts to close the gap. Every object's `spec` field holds the desired state ([Kubernetes: Controllers](https://kubernetes.io/docs/concepts/architecture/controller/)). Terraform works the same way, with one extra party. `plan` refreshes Terraform's memory (the state file) from the real world, diffs it against your configuration, and orders the resulting actions with a dependency graph built from references ([Terraform plan docs](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/cli/commands/plan.mdx)). The OpenGitOps principles take the same loop one level up. Desired state must be declarative, versioned and immutable, pulled automatically, and **continuously reconciled** ([OpenGitOps principles](https://github.com/open-gitops/documents/blob/main/PRINCIPLES.md)). Argo CD is therefore just another controller whose spec lives in Git. If you introduce the loop once in Terraform and then reuse it for Kubernetes and Argo CD, the GitOps lesson feels like a capstone rather than a new tool.

The second idea is **content addressing beats mutable names**. A Docker tag is a movable pointer, while a manifest digest names exact bytes. A multi-platform image is an index that lists one manifest per architecture ([Docker multi-platform builds](https://github.com/docker/docs/blob/main/content/manuals/build/building/multi-platform.md)). In March 2025 attackers repointed the version tags of the `tj-actions/changed-files` GitHub Action to a malicious commit that dumped CI secrets into logs ([CISA alert](https://www.cisa.gov/news-events/alerts/2025/03/18/supply-chain-compromise-third-party-github-action-cve-2025-30066)). In March 2026 the same technique hit `aquasecurity/trivy-action` ([Snyk on the Trivy compromise](https://snyk.io/articles/trivy-github-actions-supply-chain-compromise/)). GitHub's answer, workflow dependency lockfiles, pins every action, including transitive ones, to a commit and records repository IDs so that a renamed or squatted repo is detected ([GitHub docs: lockfiles](https://github.com/github/docs/blob/main/content/actions/concepts/security/workflow-dependency-lockfiles.md)). The Gradle wrapper refuses to unpack a distribution whose SHA-256 does not match `distributionSha256Sum` ([Gradle wrapper reference](https://raw.githubusercontent.com/gradle/gradle/v9.8.2/platforms/documentation/docs/src/docs/userguide/reference/runtime-configuration/gradle_wrapper.adoc)). Cosign's README says to "always sign images based on their digest... rather than a tag" ([cosign README](https://github.com/sigstore/cosign/blob/main/README.md)). One analogy, a branch name versus a commit SHA, explains Docker, Actions, GitOps and the software supply chain.

A third pattern explains most beginner errors: **a hidden middle step runs before the thing you think you ran**. The shell expands globs, variables and quotes before the program sees its arguments, so `rm *.py` hands `rm` a list of file names ([Missing Semester 2026, lecture 2](https://github.com/missing-semester/missing-semester/blob/master/_2026/command-line-environment.md)). Gradle evaluates every build script in a configuration phase before any task action executes ([Gradle build lifecycle](https://docs.gradle.org/current/userguide/build_lifecycle.html)). Terraform consults state, which stores secrets in plain text even when a variable is marked `sensitive` ([Terraform style guide](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/language/style.mdx)). Prometheus turns every unique label combination into a separate time series ([Prometheus data model](https://github.com/prometheus/docs/blob/main/docs/concepts/data_model.md)). The cure is the same everywhere: predict first, make the hidden step visible, then run. Put `echo` in front of `rm`, run `./gradlew --task-graph`, read the plan before `apply`. A JVM engineer has an advantage here, because `fun main(args: Array<String>)` is exactly what the shell builds, and SIGTERM-then-SIGKILL is the JVM shutdown-hook story that Docker and Kubernetes reuse when they stop containers.

The laptop shapes the labs in three ways. First, **on a Mac, "the host" is Docker Desktop's Linux VM**, not macOS ([Docker Desktop settings](https://github.com/docker/docs/blob/main/content/manuals/desktop/settings-and-maintenance/settings.md)). Systemd lessons therefore need a real VM such as Multipass, which uses QEMU or Apple's Virtualization Framework ([Multipass README](https://github.com/canonical/multipass)). A containerised node_exporter reports on that VM rather than on your Mac. Second, **architecture leaks everywhere**. Containers share the host kernel, so an amd64 image needs emulation on arm64 ([Docker multi-platform builds](https://github.com/docker/docs/blob/main/content/manuals/build/building/multi-platform.md)). `act` tells M-series users to pass `--container-architecture linux/amd64` ([act README](https://github.com/nektos/act/blob/main/README.md)). Jib builds amd64 images by default ([Jib Gradle README](https://raw.githubusercontent.com/GoogleContainerTools/jib/master/jib-gradle-plugin/README.md)). Meanwhile GitHub now offers arm64 Linux runners for public and private repos ([GitHub runner table](https://github.com/github/docs/blob/main/data/reusables/actions/supported-github-runners.md)). Third, **memory is the binding constraint**. Elastic asks for at least 4 GB in Docker Desktop ([Elastic Docker install](https://github.com/elastic/docs-content/blob/main/deploy-manage/deploy/self-managed/install-elasticsearch-docker-basic.md)), and kind recommends 6 to 8 GB ([kind quick start](https://kind.sigs.k8s.io/docs/user/quick-start/)). Docker Desktop itself is free for personal use and for businesses under 250 employees and $10M revenue ([Docker Desktop for Mac install](https://github.com/docker/docs/blob/main/content/manuals/desktop/setup/install/mac-install.md)). Signing in raises Docker Hub's pull allowance from 100 to 200 pulls per six hours ([Docker Hub pull limits](https://github.com/docker/docs/blob/main/content/manuals/docker-hub/usage/pulls.md)).

## Foundations: the shell, the network and a bill that cannot surprise you

### Linux: the shell rewrites your line before any program runs

Both of the established beginner curricula agree on the arc. Software Carpentry goes shell → navigating → working with files → pipes and filters → loops → scripts → finding things ([SWC episodes](https://github.com/swcarpentry/shell-novice/tree/main/episodes)). MIT's Missing Semester 2026 goes from shell and arguments, to `PATH`, to simple tools, to pipes and redirects, to tests and loops, and ends with scripts ([Missing Semester 2026, lecture 1](https://github.com/missing-semester/missing-semester/blob/master/_2026/course-shell.md)). Three ideas unlock everything later, so introduce them early and keep coming back to them. First, a line is split on whitespace into a program and a list of string arguments. Second, **the shell expands globs, variables and quotes before the program runs**. Third, every program has stdin, stdout and stderr, plus an exit code where 0 means success; `&&`, `||`, `if` and `while` all branch on that code ([Missing Semester 2026, lecture 2](https://github.com/missing-semester/missing-semester/blob/master/_2026/command-line-environment.md)).

A good five-lesson order for DevOps runs as follows. Start with terminal vs shell, command anatomy and help (`--help`, `man`, `tldr`, explainshell). Then cover paths, creating and deleting files, globs, and `PATH`. Next come reading files (`cat`, `less`, `head`, `tail -f`) and grep. Teach grep with literal strings first, then one flag at a time (`-i`, `-n`, `-c`, `-v`, `-w`, `-E`, `-o`, `-A/-B/-C`, `-r`, `-l`, `-q`), and regex last, following SWC's own sequence ([SWC "Finding Things"](https://github.com/swcarpentry/shell-novice/blob/main/episodes/07-find.md)). Lesson three covers streams, redirection, exit codes, `sort | uniq -c | sort -rn`, `awk` for columns, `sed` for substitution, `xargs`, and `jq` as "grep for JSON". Lesson four covers users and rwx permissions, processes and signals, `systemctl` and `journalctl`. Lesson five covers environment variables and `export`, dotfiles, package managers, ed25519 SSH keys with a `~/.ssh/config` alias, and finally scripts. Give scripts a fixed template: a shebang, `set -euo pipefail`, quoted expansions, argument checks and explicit exit codes, all checked with ShellCheck ([ShellCheck](https://github.com/koalaman/shellcheck)). Mention one dissent: jmmv argues the contortions strict mode needs make scripts harder to read ([jmmv.dev](https://jmmv.dev/2018/03/shell-readability-strict-mode.html)).

Almost every classic mistake comes from not seeing that expansion step, or from not knowing that redirection and `rm` act immediately. The shell has no trash bin ("Deleting Is Forever" in [SWC](https://github.com/swcarpentry/shell-novice/blob/main/episodes/03-create.md)). `sort f > f` truncates the file before `sort` reads it ([SWC pipes and filters](https://github.com/swcarpentry/shell-novice/blob/main/episodes/04-pipefilter.md)). An unquoted `find . -name *.txt` gets expanded by the shell first, so `find` searches for whatever file happened to match ([SWC](https://github.com/swcarpentry/shell-novice/blob/main/episodes/07-find.md)). `uniq` only merges adjacent duplicates, so it needs `sort` before it. `foo = bar` runs a program called `foo` ([Missing Semester lecture 2](https://github.com/missing-semester/missing-semester/blob/master/_2026/command-line-environment.md)). ShellCheck's "gallery of bad code" lists the quoting traps: unquoted `$1`, `"~/file"` (the tilde is not expanded inside quotes), and `for f in "*.ogg"`. In basic regex `|` is a literal character, so `grep "ERROR|WARN"` needs `-E`. Under `set -e`, a grep that finds nothing exits with 1 and kills the script unless you add `|| true` ([kindatechnical on strict mode](https://kindatechnical.com/shell-scripting-bash/strict-mode-set-euo-pipefail.html)). The operational habits to unlearn are reaching for `sudo` for everything, `kill -9` as a first resort (SIGKILL cannot be caught and can orphan children), and Ctrl-Z, which pauses a job rather than quitting it ([Missing Semester lecture 2](https://github.com/missing-semester/missing-semester/blob/master/_2026/command-line-environment.md)). Teach "predict, `echo` it, then run it" and most of these become visible.

The Mac adds its own traps. zsh has been the default shell since Catalina, the bundled bash is an old 3.2 ([The Next Web](https://thenextweb.com/news/why-does-macos-catalina-use-zsh-instead-of-bash-licensing)), and BSD tools differ from the GNU tools on servers: `sed -i ''`, no `grep -P`, `date -v` instead of `date -d`, and an almost entirely incompatible `stat` ([macOS and Unix: BSD vs GNU](https://cloudstreet-dev.github.io/macOS-and-Unix/part6-commands/bsd-vs-gnu.html)). The clean fix is a course-wide rule: **do the exercises inside Linux**. Use a disposable `ubuntu:24.04` container for lessons one to three, and a Multipass VM (`multipass launch lts`) for systemd, journalctl and SSH ([Multipass README](https://github.com/canonical/multipass)). Lima, OrbStack and UTM are alternatives ([Lima](https://github.com/lima-vm/lima)). Use one realistic dataset throughout, an app log plus an nginx access log that uses the documentation IP ranges, and frame each exercise as an on-call question. "Who is hammering us?" becomes `awk '{print $1}' access.log | sort | uniq -c | sort -rn | head`, built one stage at a time. Other good questions: "What's eating the disk?" (`df -h`, then `du -sh /var/* | sort -h`), "Is the service up and what is it saying?" (`systemctl status`, `journalctl -u nginx -n 50`), and "Which pods are unhealthy?" (a `jq select` over a kubectl-style JSON file). A capstone in the VM fits well: install nginx, generate traffic, report the top IPs and status codes, stop the service and read its journal, then wrap the report in a ShellCheck-clean script that exits non-zero on any 5xx. On the Mac side of the SSH lab, GitHub's docs add `UseKeychain yes` and `IgnoreUnknown UseKeychain` ([GitHub Docs: SSH keys](https://github.com/github/docs/blob/main/content/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent.md)).

### Networking: follow one request through a postal system

Teach networking in the order a real request happens. DNS turns a name into an address. IP and port are the street address and the apartment number. TCP or UDP is registered mail or a postcard. HTTP is the letter. TLS is a sealed, tamper-evident envelope delivered only after an ID check. Then come the middlemen: the reverse proxy (a receptionist), the load balancer, the CDN and the firewall (a bouncer). Only then the cloud, which is the same picture rented as API-driven building blocks. A single `curl -v https://...` touches every stage in order. Julia Evans' approach of teaching DNS through an observed query, with the "life of a DNS query" comic and a live playground, beats teaching from a list of record types ([jvns.ca: How DNS Works](https://jvns.ca/blog/2022/04/26/new-zine--how-dns-works-/); [Mess With DNS](https://messwithdns.net/about.html)). MDN's framing of HTTP as "stateless, but not sessionless", with cookies carrying the session, belongs in lesson two ([MDN: Overview of HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview)). So does Cloudflare's one-paragraph TLS handshake ([Cloudflare: TLS handshake](https://www.cloudflare.com/learning/ssl/what-happens-in-a-tls-handshake/)). For CIDR, teach the 2^(32−N) rule rather than binary drills: a /24 holds 256 addresses, and a bigger prefix number means a smaller network. In AWS every subnet loses five addresses, and subnets range from /28 to /16 ([AWS subnet sizing](https://docs.aws.amazon.com/vpc/latest/userguide/subnet-sizing.html)).

Several facts have changed recently and matter now. **Let's Encrypt certificates drop from 90 to 64 days on 10 February 2027 and to 45 days on 16 February 2028**, and Let's Encrypt says manual renewal "is not recommended" ([LE: 64-day certificates](https://letsencrypt.org/2026/10/07/64-day-certs); [LE: from 90 to 45 days](https://letsencrypt.org/2025/12/02/from-90-to-45)). Its OCSP service shut down on 6 August 2025, so tutorials that use `openssl ocsp` against it are out of date ([LE: OCSP end of life](https://letsencrypt.org/2025/08/06/ocsp-service-has-reached-end-of-life)). The HTTP-01 challenge works only on port 80 and cannot issue wildcards ([LE challenge types](https://letsencrypt.org/docs/challenge-types/)), and Let's Encrypt will not issue for `localhost` at all ([LE: certificates for localhost](https://letsencrypt.org/docs/certificates-for-localhost/)).

The beginner mistakes are the ones that "work on my machine" and then leak or fail in production. The Docker docs warn that "publishing container ports is insecure by default": `-p 8080:80` listens on every interface, and only `-p 127.0.0.1:8080:80` keeps the port on the host ([Docker port publishing](https://github.com/docker/docs/blob/main/content/manuals/engine/network/port-publishing.md)). The mirror-image bug is a server inside a container that binds to 127.0.0.1 and so cannot be reached through a published port. Learners also mistake the padlock for a statement about honesty, when it only proves control of the domain ([LE challenge types](https://letsencrypt.org/docs/challenge-types/)). They reach for `curl -k` instead of `--cacert`. They forget that a backend behind a proxy sees the proxy's address and must read `X-Forwarded-For` ([MDN: proxy servers](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Proxy_servers_and_tunneling)). They expect changed DNS records to apply everywhere at once, when caches hold answers until the TTL expires ([Cloudflare DNS proxy status](https://developers.cloudflare.com/dns/proxy-status/)). In the cloud, the classic error is treating a stateless network ACL like a stateful security group. Security groups use connection tracking, so replies are allowed automatically. NACLs need an explicit rule for the ephemeral reply ports ([AWS network ACLs](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html)). Removing a security-group rule also does not cut connections that are already tracked ([AWS connection tracking](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/security-group-connection-tracking.html)).

The two strongest free labs need only Docker Desktop and built-in macOS tools. The first is an nginx reverse proxy load-balancing two `traefik/whoami` containers on a user-defined network. Stop one backend and nginx keeps serving; stop both and you get a `502 Bad Gateway`, which teaches what a 502 means. The second is TLS on localhost with a self-signed certificate: `curl` fails with error 60, `--cacert` fixes it while keeping verification on, and `curl -v` shows the TLS 1.3 handshake lines. Lighter drills round these out. Compare `dig +trace` with the browser. Show that an `/etc/hosts` entry changes what `ping` resolves but not what `dig` returns. Split `curl -w` timing into DNS, TCP, TLS and first byte. Do CIDR arithmetic with Python's `ipaddress` module. Speak HTTP by hand through `nc`.

### Cloud: begin on a credit plan that cannot bill you

The cloud lesson reuses lesson one's networking ideas. Teach regions and availability zones, then IaaS, PaaS, SaaS and serverless, which is where the shared-responsibility line moves: with EC2 you patch the guest OS and configure the security group yourself ([AWS shared responsibility](https://docs.aws.amazon.com/wellarchitected/latest/security-pillar/shared-responsibility.html)). Then cover a service map taught as categories before names, VPCs and subnets, route tables, security groups vs NACLs, IAM roles and least privilege, and pricing. Google's comparison table is the best source for the map, but it warns that similar-looking services behave differently; GCP, for example, sets IAM on the resource itself ([Google Cloud: compare AWS and Azure services](https://docs.cloud.google.com/docs/get-started/aws-azure-gcp-service-comparison)). Teach that a subnet is "public" because of a `0.0.0.0/0 → internet gateway` route, not because of its name. Teach roles with temporary credentials rather than root keys or long-lived access keys ([AWS IAM best practices](https://aws.amazon.com/iam/resources/best-practices/)).

The 2026 free-tier rules make a safe first account possible. **AWS accounts created since 15 July 2025 can choose a Free plan** with $100 of credit at sign-up plus up to $100 more earned by exploring. The plan ends after six months or when the credits run out, and **the account then closes instead of billing**. Some actions silently upgrade you to the paid plan, including joining AWS Organizations or setting up Control Tower ([AWS Billing: choosing a plan](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html); [AWS What's New](https://aws.amazon.com/about-aws/whats-new/2025/07/aws-free-tier-credits-month-free-plan/)). **Azure gives $200 for 30 days behind a spending limit that is on by default**. When the limit is hit, VMs are stopped and storage becomes read-only, and the free quantities reset monthly without rolling over ([Azure spending limit](https://github.com/MicrosoftDocs/azure-docs/blob/main/articles/cost-management-billing/manage/spending-limit.md); [Azure: avoid charges](https://github.com/MicrosoftDocs/azure-docs/blob/main/articles/cost-management-billing/manage/avoid-charges-free-account.md)). **Google Cloud gives $300 for 90 days and does not bill until you activate a paid account**. Its always-free e2-micro VM is free only in us-west1, us-central1 or us-east1 ([Google Cloud free program](https://cloud.google.com/free-trial/)). AWS budgets alert but do not cap spending, so the routine has several parts. Stay on the trial plan. Use one region. Turn on MFA and never create root keys. Create a zero-spend budget and a small monthly budget on day one, using the template in AWS's cost-control tutorial ([AWS: control your costs](https://docs.aws.amazon.com/hands-on/latest/control-your-costs-free-tier-budgets/control-your-costs-free-tier-budgets.html)). Build every lab as one deletable unit (a resource group, project or Terraform stack) and tear it down the same day. AWS's own credit-expiry FAQ contradicts itself on 6 versus 12 months, so tell learners to check the Credits page in their console. Lesson three can be done entirely offline as design work: carve a two-AZ VPC from 10.0.0.0/16, write both route tables, solve the stateful-vs-stateless NACL puzzle, and write a read-only IAM policy for one bucket, explaining why it needs two ARNs.

## Packaging and pipelines: Docker, GitHub Actions and Gradle

### Docker: an image is a content-addressed stack, not a tiny VM

A six-lesson Docker arc builds the right picture. Lesson one: **a container is an ordinary Linux process wearing blinkers (namespaces) and a budget (cgroups)**, which Julia Evans' containers zine covers well ([wizardzines: How Containers Work](https://wizardzines.com/zines/containers/)). On a Mac that process runs inside a Linux VM. Lesson two: an image is read-only layers, and each layer holds only the diff from the one below ([Docker storage drivers](https://github.com/docker/docs/blob/main/content/manuals/engine/storage/drivers/_index.md)). OverlayFS stacks them as `lowerdir` under a container's `upperdir`, and the first write to an image file copies the whole file up ([Docker OverlayFS driver](https://github.com/docker/docs/blob/main/content/manuals/engine/storage/drivers/overlayfs-driver.md)). A manifest lists the layers by digest, and an index points to one manifest per platform. Lesson three: Dockerfiles and the **cache chain**. Once a layer changes, every later layer rebuilds ([Docker build cache](https://github.com/docker/docs/blob/main/content/manuals/build/cache/_index.md)). `COPY` checksums file metadata but ignores mtime, and a `RUN apk add` is never re-run on its own, so a rebuild a week later still has the old package ([Docker cache invalidation](https://github.com/docker/docs/blob/main/content/manuals/build/cache/invalidation.md)). Lesson four: storage and networks. Docker owns volumes, you own bind mounts, and tmpfs lives in RAM ([Docker storage overview](https://github.com/docker/docs/blob/main/content/manuals/engine/storage/_index.md)). Only **user-defined bridge networks give containers DNS by name**, through Docker's embedded resolver at `127.0.0.11`; the default bridge resolves only by IP ([Docker bridge driver](https://github.com/docker/docs/blob/main/content/manuals/engine/network/drivers/bridge.md); [Docker networking overview](https://github.com/docker/docs/blob/main/content/manuals/engine/network/_index.md)). Lesson five: Compose, including the rule that `depends_on` waits for "running", not "ready", unless you add a healthcheck condition ([Compose startup order](https://github.com/docker/docs/blob/main/content/manuals/compose/how-tos/startup-order.md)). Lesson six: production images, meaning multi-stage builds, non-root minimal bases, build secrets, multi-platform builds and attestations.

The current facts matter because two learners on "the same version" can see different behaviour. **Docker Engine 29 (10 November 2025) made the containerd image store the default for fresh installs only**. It also deprecated cgroup v1, with support promised "until at least May 2029", switched `docker image ls` to a tree view, and has since reached 29.9.2 ([Engine 29 release notes](https://github.com/docker/docs/blob/main/content/manuals/engine/release-notes/29.md)). **Compose v5 is Compose v2 plus an official Go SDK**, renumbered to avoid confusion with the old v2 and v3 file formats. The top-level `version:` key is ignored, so drop it from examples ([Compose history](https://github.com/docker/docs/blob/main/content/manuals/compose/intro/history.md)). **Docker Hardened Images became free and open source in December 2025** ([BleepingComputer](https://bleepingcomputer.com/news/security/docker-hardened-images-now-open-source-and-available-for-free)). They are pulled from `dhi.io`, are distroless and non-root by default, and offer `-dev` variants for build stages ([DHI usage docs](https://github.com/docker/docs/blob/main/content/manuals/dhi/how-to/use.md)). `docker debug`, which opens a shell in images that have none, has been free since Desktop 4.49 ([Desktop release notes](https://github.com/docker/docs/blob/main/content/manuals/desktop/release-notes.md)). `docker build --check` lints Dockerfiles ([Docker build checks](https://github.com/docker/docs/blob/main/content/manuals/build/checks.md)).

The misconceptions to pre-empt follow from the mechanics. "Containers are lightweight VMs" is wrong: they share the kernel, which is why amd64 images need emulation on Apple Silicon. "`RUN rm` makes my image smaller" is wrong: the bytes stay in the earlier layer. "`ARG` or `ENV` is fine for a token" is wrong: build arguments persist in the image, so use `RUN --mount=type=secret` ([Docker build secrets](https://github.com/docker/docs/blob/main/content/manuals/build/building/secrets.md)). "`localhost` inside a container is my Mac" is wrong: it is the container itself. "`-p 8080:80` is local" is wrong. "Editing files under a volume's host path is fine" is wrong: Docker calls it undefined behaviour. Free exercises map one-to-one onto these models:

- Build layers with `docker container commit` and inspect them with `docker image history` ([Docker: understanding image layers](https://github.com/docker/docs/blob/main/content/get-started/docker-concepts/building-images/understanding-image-layers.md)).
- Run `dive` to see wasted bytes ([dive](https://github.com/wagoodman/dive)).
- Reorder a Dockerfile so the dependency manifest is copied before the source, then add a cache mount ([Docker: optimize cache](https://github.com/docker/docs/blob/main/content/manuals/build/cache/optimize.md)).
- Read an index with `docker buildx imagetools inspect --raw`.
- Ping containers by name on the default bridge, where it fails, and then on a user-defined network, where it works.
- Mount an empty named volume over nginx's web root and watch it fill with the image's content ([Docker volumes](https://github.com/docker/docs/blob/main/content/manuals/engine/storage/volumes.md)).
- Pull `dhi.io/python:3.13`, watch `docker exec ... sh` fail, then get in with `docker debug`.

### GitHub Actions: untrusted input plus secrets equals compromise

Teach CI/CD as the gate on merging, not just "tests on a server". The vocabulary is event → workflow → job → step → action, all running on a runner. **Every job is a fresh VM**, so nothing carries over without a cache or an artifact. Then move through a first workflow (triggers, `uses` vs `run`, choosing a runner label, running locally with `act`), a real pipeline (cache vs artifact, cache keys, matrix builds, artifacts, service containers), and advanced workflows (contexts, expressions and the implicit `success()` in every `if:`, job outputs through `$GITHUB_OUTPUT`, reusable workflows vs composite actions, concurrency). Finish with shipping safely: secrets and their redaction limits, script injection, least-privilege `GITHUB_TOKEN`, `pull_request` vs `pull_request_target`, environments, OIDC and supply-chain pinning.

The 2026 numbers have changed. GitHub.com now meters **included usage in dollars: $12 a month on the Free plan**, which at $0.006 per Linux x64 minute is about 2,000 minutes ([GitHub included quotas](https://github.com/github/docs/blob/main/data/reusables/billing/actions-included-quotas.md); [runner prices](https://github.com/github/docs/blob/main/data/reusables/billing/actions-standard-runner-prices.md)). Standard runners remain **free in public repositories**, as do self-hosted runners ([GitHub Actions billing](https://github.com/github/docs/blob/main/data/reusables/actions/actions-billing.md)), so course practice repos should be public. The cache holds 10 GB per repository and evicts entries unused for 7 days. Since June 2026, `pull_request_target`, `issue_comment` and similar untrusted triggers get read-only cache access ([dependency caching reference](https://github.com/github/docs/blob/main/content/actions/reference/workflows-and-actions/dependency-caching.md); [GitHub changelog](https://github.blog/changelog/2026-06-26-read-only-actions-cache-for-untrusted-triggers/)). Artifacts from upload-artifact v4 onward are immutable, so matrix legs cannot append to one artifact name ([upload-artifact README](https://github.com/actions/upload-artifact/blob/main/README.md)). The default `concurrency` queue silently replaces older pending runs, and `queue: max` now allows up to 100 runs to wait in order ([control workflow concurrency](https://github.com/github/docs/blob/main/content/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency.md)). Environment wait timers and required reviewers work on Free, Pro and Team only in public repos ([environments availability](https://github.com/github/docs/blob/main/data/reusables/gated-features/environments.md)).

Security moved fastest. Most real compromises follow one pattern: **untrusted input reaches a context that holds secrets**. Under `pull_request_target`, checking out a fork's head SHA and running its build hands that code the base repo's token and secrets. That is the "pwn request" ([GitHub: securely using pull_request_target](https://github.com/github/docs/blob/main/content/actions/reference/security/securely-using-pull_request_target.md); [GitHub Security Lab](https://securitylab.github.com/resources/github-actions-preventing-pwn-requests/)). Interpolating `${{ github.event.pull_request.title }}` straight into `run:` lets a crafted PR title execute commands; the fix is to pass it through `env:` ([GitHub: script injections](https://github.com/github/docs/blob/main/content/actions/concepts/security/script-injections.md)). Secret redaction "is not guaranteed" for transformed or structured values ([GitHub secure use reference](https://github.com/github/docs/blob/main/content/actions/reference/security/secure-use.md)). GitHub responded with secure defaults:

- **`actions/checkout` v7 refuses to check out fork PR code under `pull_request_target` or `workflow_run`** unless you opt in explicitly ([checkout README](https://github.com/actions/checkout/blob/main/README.md)).
- A default policy blocking `pull_request_target` in public repos runs in evaluate mode now. The docs say it will be enforced on **2 December 2026** ([GitHub docs](https://github.com/github/docs/blob/main/content/actions/reference/security/securely-using-pull_request_target.md)), while press coverage says 2 November ([Socket](https://socket.dev/blog/github-actions-checkout-blocks-pull-request-target-checkouts)). Treat the docs date as authoritative and the conflict as real.
- **Workflow dependency lockfiles** entered public preview on 14 October 2026 ([GitHub changelog](https://github.blog/changelog/2026-10-14-github-actions-workflow-lockfiles-in-public-preview/)).

OIDC replaces stored cloud keys. `permissions: id-token: write` only lets the job request a JWT, which the cloud exchanges for a short-lived credential scoped to that job ([GitHub: OpenID Connect](https://github.com/github/docs/blob/main/content/actions/concepts/security/openid-connect.md)). Repositories created before 2 February 2023 may still default to a read/write `GITHUB_TOKEN` ([GitHub changelog 2023](https://github.blog/changelog/2023-02-02-github-actions-updating-the-default-github_token-permissions-to-read-only/)).

The mistakes to teach explicitly, roughly in the order a newcomer hits them:

1. Inlining `${{ }}` in `run:`.
2. Leaving `permissions:` unset on an old repo.
3. Using `@main` or a movable tag for third-party actions.
4. Reaching for `pull_request_target` "to get secrets on fork PRs".
5. Cache keys without `runner.os` and a lockfile hash.
6. Reusing one artifact name across matrix legs.
7. Expecting top-level `env` to reach a reusable workflow; it doesn't, so use `vars` ([reusable workflow reference](https://github.com/github/docs/blob/main/content/actions/reference/workflows-and-actions/reusing-workflow-configurations.md)).
8. Not knowing the default concurrency queue drops pending runs.

Every one of these has a free lab in a public repo:

- A PR whose title contains `"; echo pwned; #` against a workflow that inlines the title, then the `env:` fix.
- A 2×2 matrix including `ubuntu-24.04-arm` that fails on a shared artifact name.
- Three quick pushes under `single` versus `queue: max`.
- Replacing tags with full SHAs.
- Setting `permissions: {}` at the top and adding back only what each job needs.

Run everything locally with `act` first and validate on GitHub, because `act` is an approximation ([act README](https://github.com/nektos/act/blob/main/README.md)).

### Gradle: the tool a Kotlin engineer already uses, now with a model behind it

For a Kotlin engineer, Gradle is home turf. The lesson's job is to replace copy-paste habits with a model, in this order: tasks → task graph → lifecycle → files → wrapper → running tasks. A task is a unit of work with declared inputs and outputs, and one that is `UP-TO-DATE` was *verified* unchanged, not skipped blindly. Gradle builds a directed acyclic graph of only the tasks you requested, which `--task-graph` prints without running anything ([Gradle 9.1 release notes](https://raw.githubusercontent.com/gradle/gradle/v9.1.0/platforms/documentation/docs/src/docs/release/notes.md)). The lifecycle has three phases: initialization reads settings, configuration runs the build scripts to *describe* the graph, and execution runs task actions ([Gradle build lifecycle](https://docs.gradle.org/current/userguide/build_lifecycle.html)). The wrapper acts as a lockfile for the build tool itself. After that come dependencies by configuration. `implementation` vs `api` is private vs public visibility for your dependencies, and `api` dependencies land on consumers' compile classpath ([Java Library plugin](https://docs.gradle.org/current/userguide/java_library_plugin.html)). Then version catalogs, platforms and BOMs ([Gradle platforms](https://raw.githubusercontent.com/gradle/gradle/v9.8.2/platforms/documentation/docs/src/docs/userguide/reference/dependency-management/centralizing-dependencies/platforms.adoc)), multi-project builds, and convention plugins. Gradle now prefers those **in an included `build-logic` build, not `buildSrc`**, because "any change in `buildSrc` causes the entire build to become out-of-date" ([Gradle best practices: structuring builds](https://raw.githubusercontent.com/gradle/gradle/v9.8.2/platforms/documentation/docs/src/docs/userguide/best-practices/best_practices_structuring_builds.adoc)). The third lesson is speed and reliability. Speed comes from up-to-date checks, the build cache keyed on a hash of task inputs ([Gradle build cache](https://raw.githubusercontent.com/gradle/gradle/v9.8.2/platforms/documentation/docs/src/docs/userguide/optimizing-builds/build-cache/build_cache.adoc)), the configuration cache, the daemon and parallel execution. Reliability comes from pinning: wrapper checksums, toolchains, dependency locking ([dependency locking](https://raw.githubusercontent.com/gradle/gradle/v9.8.2/platforms/documentation/docs/src/docs/userguide/reference/dependency-management/dependency-management/dependency_locking.adoc)) and dependency verification ([dependency verification](https://docs.gradle.org/current/userguide/dependency_verification.html)).

**The current release is Gradle 9.8.2 (19 October 2026)** ([services.gradle.org](https://services.gradle.org/versions/current)). The 9.x line started in July 2025, and the changes that matter to a beginner are these:

- **The configuration cache is the "preferred mode of execution"**, `gradle init` turns it on, and Gradle aims to make it the default in Gradle 10 ([What's new in Gradle 9](https://gradle.org/whats-new/gradle-9/)).
- **The daemon now needs Java 17+**, while toolchains can still compile for Java 8+. Teach the split between "the JDK that runs Gradle" and `kotlin { jvmToolchain(21) }` early ([Gradle 9.0.0 release notes](https://raw.githubusercontent.com/gradle/gradle/v9.0.0/platforms/documentation/docs/src/docs/release/notes.md)).
- Gradle 9 removed `jcenter()`, the `-b`/`-c` flags, the Convention API, `project.exec` and the Kotlin DSL `"name"()` task syntax. A `test` task that discovers no tests now fails ([Gradle 9 upgrade guide](https://raw.githubusercontent.com/gradle/gradle/v9.8.0/platforms/documentation/docs/src/docs/userguide/releases/upgrading/upgrading_major_version_9.adoc)).
- Kotlin and the Kotlin Gradle plugin are at 2.4.21, with 2.5.0 planned for December 2026 ([Kotlin releases](https://kotlinlang.org/docs/releases.html)).

Any pre-2025 blog post is therefore suspect.

The classic mistakes:

- **Running a global `gradle` instead of `./gradlew`**; the setup-gradle docs call the wrapper "the recommended way to execute any Gradle build" ([gradle/actions README](https://raw.githubusercontent.com/gradle/actions/main/README.md)).
- **Doing real work at configuration time.** With the configuration cache on, touching `project` inside `doLast` now fails outright.
- Pasting logic into every build script instead of using convention plugins, and using `allprojects {}` blocks.
- Defaulting to `api`.
- Assuming the version you declared is the version you got. When two versions meet in the graph, Gradle picks the highest and `dependencyInsight` reports "By conflict resolution" ([Gradle: constraints and conflicts](https://raw.githubusercontent.com/gradle/gradle/v9.8.2/platforms/documentation/docs/src/docs/userguide/reference/dependency-management/basics/dependency_constraints_conflicts.adoc)).

In CI, use `gradle/actions/setup-gradle@v6` and **do not also add `actions/cache` on `~/.gradle` or setup-java's `cache: gradle`**, because "either of these mechanisms may interfere". Branches other than the default only read the cache. Configuration-cache entries can hold secrets, so carry them between runs only with a `cache-encryption-key` ([setup-gradle docs](https://raw.githubusercontent.com/gradle/actions/main/docs/setup-gradle.md)). Note that v6's default "enhanced" cache provider is a proprietary library: free for public repos, in "free preview" for private ones, with a plain MIT `basic` provider as the alternative ([gradle/actions DISTRIBUTION.md](https://raw.githubusercontent.com/gradle/actions/main/DISTRIBUTION.md)). For containers, a multi-stage Dockerfile is the most transparent teaching choice. Jib pushes without a Docker daemon but defaults to amd64 ([Jib README](https://raw.githubusercontent.com/GoogleContainerTools/jib/master/jib-gradle-plugin/README.md)), and its changelog lists Gradle 9 fixes but no configuration-cache support, so it needs `--no-configuration-cache` today ([Jib changelog](https://raw.githubusercontent.com/GoogleContainerTools/jib/master/jib-gradle-plugin/CHANGELOG.md)).

The best labs make the model visible:

- A ten-line lifecycle demo: put `println` in settings, in a build script and in `doLast`, run it twice, and watch the configuration cache skip the first two phases.
- Edit a comment, then a function body, then a public signature in a library, and record which tasks re-run.
- Flip `implementation` to `api` and watch a compile error disappear.
- Add a `junit-bom` platform and watch `dependencyInsight` change.
- Run `clean build` with the build cache on and count the `FROM-CACHE` lines.
- Lock dependencies, then bump a catalog version and watch the build fail.

Learners should also *read* Maven fluently. It remains ubiquitous in enterprise Java, while Gradle is mandatory for Android and Kotlin Multiplatform ([Gradle: Maven vs Gradle](https://gradle.org/maven-vs-gradle)).

## Desired state everywhere: Terraform, Kubernetes and Argo CD

### Terraform and OpenTofu: config, state and reality in a three-way diff

Teach Terraform as a three-way reconciliation. Your configuration is the desired state, the state file is Terraform's memory of what it built, and the real world is what exists. Drift, `moved`, `import`, `count` vs `for_each` and remote state all hang off that triangle. A five-lesson arc works:

1. **Why IaC and declarative vs imperative.** Terraform has no ordinary loops or ifs ([Terraform: Up & Running, ch. 5](https://www.oreilly.com/library/view/terraform-up-and/9781098116736/ch05.html)). Install it, meet providers, resources and `init`/`plan`/`apply`/`destroy`, and learn to read a plan: `+ create`, `~ update in-place`, `-/+` replace, `(known after apply)`, `# forces replacement`.
2. **HCL**, practised in `terraform console`: references (which draw the graph's edges), types, variables with validation and precedence, locals, outputs, templates, `for` expressions, `count` vs `for_each`, and dynamic blocks.
3. **State**: what it holds, locking, remote backends, `moved`/`removed`/`import` blocks, drift with `-refresh-only`, and keeping secrets out of state with ephemeral values and write-only arguments ([Terraform: manage sensitive data](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/language/manage-sensitive-data/index.mdx)).
4. **Modules, environments and `terraform test`** with `mock_provider`.
5. **A real cloud and CI.**

**Terraform 1.17.1 shipped on 28 October 2026**, and 1.17 made Terraform Policy generally available ([Terraform v1.17 changelog](https://github.com/hashicorp/terraform/blob/v1.17/CHANGELOG.md)). **OpenTofu is at 1.13.5**, with the 1.13 series supported until 1 August 2027 and requiring macOS 13 or later ([OpenTofu v1.13 changelog](https://github.com/opentofu/opentofu/blob/v1.13/CHANGELOG.md)). The S3 backend's native locking (`use_lockfile = true`) went GA in 1.11, and **DynamoDB-based locking is deprecated**, so every pre-2025 tutorial showing `dynamodb_table` is out of date ([Terraform S3 backend](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/language/backend/s3.mdx); [v1.11 changelog](https://github.com/hashicorp/terraform/blob/v1.11/CHANGELOG.md)). HCP Terraform's Free plan is capped at 500 managed resources ([HCP Terraform plans](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform-docs-common/docs/cloud-docs/overview/manage-plan.mdx)). Third-party reports say the legacy free plan ended on 31 March 2026 ([Scalr](https://scalr.com/learning-center/hcp-terraform-free-tier-is-being-discontinued-what-you-need-to-know)). The two tools share a language and workflow. OpenTofu alone offers state encryption ([OpenTofu state encryption](https://github.com/opentofu/opentofu/blob/main/website/docs/language/state/encryption.mdx)) and provider `for_each`; Terraform alone offers HCP Terraform, Stacks and Policy. OpenTofu's migration guide is built around backing up state ([OpenTofu migration guide](https://github.com/opentofu/opentofu/blob/main/website/docs/intro/migration/migration-guide.mdx)).

The classic mistakes persist:

- **`count` index shifting.** Removing the first item of a counted list re-addresses every later instance, while `for_each` keys survive. The docs' rule is `count` for nearly identical instances and `for_each` when instances differ ([Terraform count](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/language/meta-arguments/count.mdx)).
- **Committing state or secret `.tfvars` files.**
- **Believing `sensitive = true` keeps a value out of state.** It only hides it in output ([Terraform style guide](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/language/style.mdx)).
- **Using `-target` routinely** ([plan docs](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/cli/commands/plan.mdx)).
- **Treating CLI workspaces as environment isolation.** They share one backend, so use a root directory per environment ([Terraform workspaces](https://github.com/hashicorp/web-unified-docs/blob/main/content/terraform/v1.17.x/docs/cli/workspaces/index.mdx)).
- **Leaving provider and module versions unpinned.**
- Newer traps: assuming an `import` block writes matching config, assuming `state rm` deletes anything (it only makes Terraform forget), and pinning CI actions to mutable tags, which the March 2026 trivy-action compromise (CVE-2026-33634) punished ([Snyk](https://snyk.io/articles/trivy-github-actions-supply-chain-compromise/)).

On a real cloud, use the AWS provider with short-lived credentials: SSO or `aws login` locally, and GitHub OIDC in CI through `aws-actions/configure-aws-credentials`. Repositories created after 15 July 2026 get immutable OIDC subject claims that embed org and repo IDs ([configure-aws-credentials](https://github.com/aws-actions/configure-aws-credentials); [GitHub changelog](https://github.blog/changelog/2026-04-23-immutable-subject-claims-for-github-actions-oidc-tokens/)). Run plan on the PR, apply on merge behind an environment approval, and gate with tflint, `trivy config` (tfsec's successor) and checkov ([tfsec README](https://github.com/aquasecurity/tfsec); [checkov](https://github.com/bridgecrewio/checkov)).

Every core concept except cloud auth and remote backends can be taught without a cloud account. Use `hashicorp/random` and `hashicorp/local` for instant plans, then nginx through `kreuzwerker/docker` so learners can `curl` what they built. HashiCorp's own "Get Started – Docker" tutorial takes this route ([HashiCorp Docker tutorial](https://developer.hashicorp.com/terraform/tutorials/docker-get-started); [kreuzwerker provider docs](https://github.com/kreuzwerker/terraform-provider-docker/blob/master/docs/index.md)). The tested labs:

- The count-vs-for_each shift on a list of three names.
- Renaming a resource without and then with a `moved` block.
- Deleting a managed file by hand and running `plan -refresh-only`.
- Importing a `random_string` and iterating until the plan is clean.
- Lock contention between two terminals.
- The hard error when an ephemeral password flows into a non-write-only attribute.
- A local module tested with `terraform test`.

Mac users who share a lock file with Linux CI should record hashes for both platforms with `terraform providers lock -platform=darwin_arm64 -platform=linux_amd64`. That is an inference from Terraform's own warning text, so verify it on a Mac before teaching it.

### Kubernetes: thermostats, disposable Pods and labels as glue

Four intuitions recur through every Kubernetes lesson. Control loops chase the `spec`. **Pods are "relatively ephemeral, disposable entities"** that controllers create and replace ([Kubernetes: Pods](https://kubernetes.io/docs/concepts/workloads/pods/)). Services give churning Pods one stable address and DNS name ([Kubernetes: Service](https://kubernetes.io/docs/concepts/services-networking/service/)). **Labels and selectors are the glue** connecting Deployments to ReplicaSets to Pods, and Services, NetworkPolicies and PodDisruptionBudgets to Pods ([Labels and selectors](https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/)). A nine-lesson order works:

1. **Architecture.** API server, etcd, scheduler and controller manager; kubelet, container runtime and kube-proxy; CoreDNS and CNI addons; kind, where each node is a Docker container.
2. **Pods, kubectl and YAML.** Phases vs the STATUS column, restart policy, init containers and native sidecars, labels vs annotations, namespaces, kubeconfig contexts.
3. **Deployments and rollouts.** A new revision happens only when `.spec.template` changes, with 25% max-surge and max-unavailable defaults and a 600-second progress deadline ([Kubernetes: Deployments](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/)).
4. **Services**, EndpointSlices, Service DNS and NetworkPolicy.
5. **ConfigMaps and Secrets**, including the fact that environment-variable consumers don't see updates until a restart ([ConfigMaps](https://kubernetes.io/docs/concepts/configuration/configmap/)).
6. **Health and resources.** Probes, requests and limits, QoS classes, HPA, in-place resize, scheduling, PDBs.
7. **Traffic and storage.** Gateway API and Ingress, PVs and PVCs, StatefulSets.
8. **Helm and Kustomize**, framed as templating vs patching.
9. **Troubleshooting.** A bottom-up flow from Pods to Service to Gateway, `kubectl debug`, k9s and RBAC ([Learnkube troubleshooting guide](https://learnkube.com/troubleshooting-deployments)).

**Kubernetes 1.37 "Garhwal" shipped on 26 August 2026** (patch 1.37.2). It made KYAML and `metrics.k8s.io` stable, put HPA scale-to-zero into beta and deprecated kube-dns ([Kubernetes v1.37 release](https://kubernetes.io/blog/2026/08/26/kubernetes-v1-37-release/)). Recent releases changed what beginners should learn. Native sidecars (init containers with `restartPolicy: Always`) went GA in 1.33 ([v1.33 release](https://kubernetes.io/blog/2025/04/23/kubernetes-v1-33-release/)). In-place Pod resize went GA in 1.35, and 1.35 also switched cgroup v1 support off by default ([v1.35 release](https://kubernetes.io/blog/2025/12/17/kubernetes-v1-35-release/)). **The community ingress-nginx controller was retired on 24 March 2026**, with no further releases or security fixes ([ingress-nginx retirement](https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/)). The Ingress API is frozen, and Gateway API, now at v1.7.0, is the recommended path ([Ingress docs](https://kubernetes.io/docs/concepts/services-networking/ingress/); [Gateway API v1.7 changelog](https://github.com/kubernetes-sigs/gateway-api/blob/main/CHANGELOG/1.7-CHANGELOG.md)). **Helm 4 replaced Helm 3**. `--atomic` became `--rollback-on-failure` ([Helm 4 overview](https://helm.sh/docs/overview)), and Helm 3's security fixes end on 10 February 2027 ([Helm 3 end of life](https://helm.sh/blog/helm-v3-end-of-life)). The Kubernetes Dashboard is archived in favour of Headlamp ([Kubernetes blog](https://kubernetes.io/blog/2026/06/01/dashboard-to-headlamp/)). kind v0.33.0 ships a Kubernetes 1.37.0 node image ([kind](https://github.com/kubernetes-sigs/kind)).

Most beginner failures come from treating Kubernetes like a VM host, and the official sources warn about each one:

- **`:latest` images.** They also silently force `imagePullPolicy: Always` ([Kubernetes: images](https://kubernetes.io/docs/concepts/containers/images/)).
- **Missing resource requests**, pitfall number one in the project's own blog list ([7 Common Kubernetes Pitfalls](https://kubernetes.io/blog/2025/10/20/seven-kubernetes-pitfalls-and-how-to-avoid/)).
- **Confusing CPU and memory limits.** CPU over its limit is throttled; memory over its limit is OOM-killed ([Resource management](https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)).
- **Aggressive liveness probes**, which "can lead to cascading failures" ([Probes](https://kubernetes.io/docs/concepts/workloads/pods/probes/)).
- **Believing Secrets are encrypted.** They sit unencrypted in etcd by default ([Secrets](https://kubernetes.io/docs/concepts/configuration/secret/)).
- **Reading `CrashLoopBackOff` as a phase.** It is a display string, not one of the five phases ([Pod lifecycle](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/)).
- **Assuming namespaces isolate traffic.** Every Pod accepts all traffic until a NetworkPolicy selects it ([Network Policies](https://kubernetes.io/docs/concepts/services-networking/network-policies/)).

Every lesson can run free on one kind cluster with one control-plane node and two workers ([kind quick start](https://kind.sigs.k8s.io/docs/user/quick-start/)). Add metrics-server with `--kubelet-insecure-tls` for the HPA lab ([metrics-server](https://github.com/kubernetes-sigs/metrics-server); [HPA walkthrough](https://kubernetes.io/docs/tasks/run-application/horizontal-pod-autoscale-walkthrough/)). Add cloud-provider-kind for LoadBalancer and Gateway, which on a Mac is reached through a port-mapped container on localhost ([cloud-provider-kind](https://github.com/kubernetes-sigs/cloud-provider-kind); [Gateway API with kind](https://kubernetes.io/blog/2026/01/28/experimenting-gateway-api-with-kind/)). The best exercises are "break it, observe, fix it" loops that make the control loop visible:

- Delete the CoreDNS Pods and watch them return.
- Roll out a nonexistent image tag and watch the old Pods keep serving until `rollout undo`.
- Strip a label from a Pod and watch the ReplicaSet orphan it and create a replacement.
- Typo a Service selector and see zero endpoints.
- Apply a default-deny NetworkPolicy.
- Run a memory hog until it is OOMKilled.
- Watch `kubectl drain` block on a PodDisruptionBudget.
- Play "break-it bingo" with six broken manifests diagnosed through get → describe → logs `--previous` → events → endpoints → port-forward.

Use multi-arch images on Apple Silicon to avoid `exec format error`.

### Argo CD: the same control loop with Git as the spec

GitOps works best taught as the course's natural capstone. Start with the four OpenGitOps principles. A floating `:latest` tag violates "versioned and immutable" ([OpenGitOps](https://github.com/open-gitops/documents/blob/main/PRINCIPLES.md)). Then teach:

1. The `Application` CRD: a source, a destination and a project.
2. The two independent statuses, sync and health.
3. Install and a first app.
4. Change detection by polling roughly every three minutes, or instantly with webhooks ([Argo CD FAQ](https://argo-cd.readthedocs.io/en/stable/faq/)).
5. Automated sync with `prune` and `selfHeal` ([Automated Sync Policy](https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/)).
6. Leaving room for controllers. If an HPA owns `replicas`, omit `replicas` from Git or the two will fight ([Argo CD best practices](https://argo-cd.readthedocs.io/en/stable/user-guide/best_practices/)).

The practice lesson covers a separate config repo, promotion as a pull request that copies an immutable tag between overlays, ApplicationSets that stamp out one app per environment ([ApplicationSet](https://argo-cd.readthedocs.io/en/stable/operator-manual/applicationset/)), app-of-apps (which the docs call "an admin-only tool": [cluster bootstrapping](https://argo-cd.readthedocs.io/en/stable/operator-manual/cluster-bootstrapping/)), sync waves and hooks ([sync waves](https://argo-cd.readthedocs.io/en/stable/user-guide/sync-waves/)), and destination-cluster secret management with Sealed Secrets or External Secrets ([Argo CD secret management](https://argo-cd.readthedocs.io/en/stable/operator-manual/secret-management/)).

**Argo CD 3.5.6 is the stable release** (3.6 is in release candidate), and 3.x broke older tutorials in three ways. Since 3.3, the ApplicationSet CRD is too large for client-side apply, so installs need `kubectl apply --server-side --force-conflicts` ([Argo CD getting started](https://argo-cd.readthedocs.io/en/stable/getting_started/); [upgrading 3.2→3.3](https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/3.2-3.3/)). 3.0 made annotation-based resource tracking the default and stopped RBAC `update`/`delete` from cascading to managed resources ([upgrading 2.14→3.0](https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/2.14-3.0/)). 3.5 bundles Helm 4.2.0, ignores `helm.version: v3`, and adds a beta Source Hydrator that commits rendered manifests to Git for review ([upgrading 3.4→3.5](https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/3.4-3.5/); [Source Hydrator](https://argo-cd.readthedocs.io/en/stable/user-guide/source-hydrator/)).

The key beginner mistake is hand-editing a GitOps-managed object. Without self-heal, a `kubectl edit` leaves the app OutOfSync, because live changes "will not trigger automated sync". Without `prune`, deleting YAML from Git leaves orphaned resources ([Automated Sync Policy](https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/)). Injecting secrets during manifest generation leaves them in plaintext in Argo CD's Redis cache ([secret management](https://argo-cd.readthedocs.io/en/stable/operator-manual/secret-management/)). The free lab on kind uses the guestbook app. Sync it manually, enable auto-sync, then `kubectl scale` the deployment and watch it go OutOfSync until `selfHeal` reverts it. Delete a manifest from your fork and see nothing pruned until `prune: true`. Then build `base` plus `overlays/{dev,staging,prod}` in a public repo, generate three apps with a list-generator ApplicationSet, promote by PR, and add a PostSync smoke-test Job that fails the sync when broken.

## Observability: metrics as slopes, logs as events, traces as parcels

### Prometheus: read counters by their slope and price every label

Start from the user rather than the server. The four golden signals (latency, traffic, errors, saturation), RED (rate, errors, duration, for services) and USE (utilization, saturation, errors, for resources) are three lenses on one question. Grafana's guidance compresses it neatly: "USE reports on causes... RED reports on user experience... alerting should be done on RED dashboards" ([Grafana dashboard best practices](https://github.com/grafana/grafana/blob/main/docs/sources/visualizations/dashboards/build-dashboards/best-practices/index.md); [The RED Method](https://grafana.com/blog/the-red-method-how-to-instrument-your-services/); [The USE Method](https://www.brendangregg.com/usemethod.html)). SLOs turn "good enough" into a number. The error budget is 1 − SLO, and releases pause when it is spent ([SRE book: Service Level Objectives](https://sre.google/sre-book/service-level-objectives/); [SRE book: Embracing Risk](https://sre.google/sre-book/embracing-risk/)). A 99.9% SLO over 30 days allows 43.2 minutes of total failure. Prometheus's own advice is to "alert on symptoms" and keep pages few ([Prometheus alerting practices](https://github.com/prometheus/docs/blob/main/docs/practices/alerting.md)). A common multi-window rule pages at a 14.4× burn rate over an hour, which is 2% of a 30-day budget gone ([How to alert on SLOs](https://medium.com/google-cloud/how-to-alert-on-slos-2a5ce8c4e7dd)).

Then teach the architecture:

1. **The pull model**, where a failed scrape shows up as `up == 0` and Pushgateway is only for service-level batch jobs ([Prometheus overview](https://github.com/prometheus/docs/blob/main/docs/introduction/overview.md); [pushing](https://github.com/prometheus/docs/blob/main/docs/practices/pushing.md)).
2. **Scrape config**, where the default interval is one minute ([configuration](https://github.com/prometheus/prometheus/blob/main/docs/configuration/configuration.md)).
3. **Exporters.**
4. **Series = metric name plus labels.**
5. **The four metric types.** Never `rate()` a gauge ([Understanding metric types](https://prometheus.io/docs/tutorials/understanding_metric_types/)).
6. **Retention**, 15 days by default ([Prometheus storage](https://github.com/prometheus/prometheus/blob/main/docs/storage.md)).
7. **Cardinality.** Keep most metrics under about 10 series and investigate anything over 100 ([Prometheus instrumentation](https://github.com/prometheus/docs/blob/main/docs/practices/instrumentation.md); [Cardinality is key](https://www.robustperception.io/cardinality-is-key/)).

PromQL comes next: instant vs range vectors → `rate()` on counters → aggregate *after* rate → `histogram_quantile` over summed buckets that keep `le` → `offset` and binary operators → recording rules ([PromQL functions](https://prometheus.io/docs/prometheus/latest/querying/functions/); [Histograms and summaries](https://prometheus.io/docs/practices/histograms/)). Close with alerting rules and `for:`, Alertmanager's grouping, inhibition and silences ([Alertmanager](https://prometheus.io/docs/alerting/latest/alertmanager/)), kube-prometheus-stack, and long-term storage with Thanos or Mimir.

**Prometheus 3.15.1 (21 October 2026) is current.** 3.0 brought a new UI, UTF-8 metric names and an OTLP receiver flag, and removed 2.x flags such as `--enable-feature=agent` in favour of `--agent`. Native histograms became stable in 3.8 but stay opt-in through `scrape_native_histograms` ([Prometheus CHANGELOG](https://github.com/prometheus/prometheus/blob/main/CHANGELOG.md); [Prometheus 3.0](https://prometheus.io/blog/2024/11/14/prometheus-3-0/)). kube-prometheus-stack is at chart 92.16.0 and is now installed from an OCI registry. Its classic gotcha is that **ServiceMonitors are ignored unless they carry the Helm release label**, unless you set `serviceMonitorSelectorNilUsesHelmValues=false` ([kube-prometheus-stack](https://github.com/prometheus-community/helm-charts/tree/main/charts/kube-prometheus-stack)).

The beginner errors are well documented, and most can be reproduced in a lab:

- **A rate window shorter than about four scrape intervals**, which can return nothing ([What range should I use with rate()?](https://www.robustperception.io/what-range-should-i-use-with-rate/)).
- **Summing before rating**, which breaks counter-reset handling ([Rate then sum, never sum then rate](https://www.robustperception.io/rate-then-sum-never-sum-then-rate/)).
- **Averaging precomputed percentiles**, which the docs flag as "BAD"; aggregate the buckets, then take the quantile ([Histograms and summaries](https://prometheus.io/docs/practices/histograms/)).
- **Using `irate` in alerts**, where a brief dip resets `for:` ([Avoid irate() in alerts](https://www.robustperception.io/avoid-irate-in-alerts/)).
- **User IDs or emails as labels.**
- **Expecting integers from `increase()`**, which extrapolates ([PromLabs on rates](https://promlabs.com/blog/2021/01/29/how-exactly-does-promql-calculate-rates/)).
- **Coarse buckets.** `histogram_quantile` interpolates linearly inside a bucket, so it can report a p95 above any request's real latency.
- **Long-window rates right after a restart**, which read low until the window fills.

On a Mac, a containerised node_exporter reports Docker Desktop's VM, so run the native darwin-arm64 binary to monitor the laptop itself ([node_exporter](https://github.com/prometheus/node_exporter)). The free lab is a Compose stack of `prom/prometheus:v3.15.1`, node_exporter, Alertmanager, Grafana, an instrumented Flask app and a webhook receiver, all published for arm64. In it:

- Stop the app and watch `up` fall to 0.
- Restart it and watch the counter reset, which motivates `rate()`.
- Add a `user_id` label and watch the series count explode.
- Work through a "fix my query" set.
- Write a burn-rate alert and test it with `promtool`.
- Make a target-down alert inhibit the error-ratio alert.

### Grafana: dashboards are JSON, and old images are frozen

Grafana is the UI layer, and it stores no metrics itself. Teach it in this order:

1. Data sources, panels, units and thresholds.
2. Transformations.
3. Variables, so one dashboard serves many hosts.
4. **"Dashboard = JSON = code"**, provisioned from files in `/etc/grafana/provisioning`. Provisioned dashboards cannot be saved from the UI when `allowUiUpdates` is false. Literal dollar signs must be escaped as `$$`. On Docker for Mac, `updateIntervalSeconds` should be above 10, because file-watch events do not cross bind mounts ([Grafana provisioning](https://github.com/grafana/grafana/blob/main/docs/sources/administration/provisioning/index.md)).
5. Design: a dashboard "should tell a story or answer a question". Use a RED layout, and keep editing out of the browser in mature teams ([Grafana dashboard best practices](https://grafana.com/docs/grafana/latest/dashboards/build-dashboards/best-practices/)).
6. Beyond dashboards: Grafana Alerting, "built on the Prometheus alerting model" with contact points and notification policies ([alerting fundamentals](https://github.com/grafana/grafana/blob/main/docs/sources/alerting/fundamentals/_index.md)).
7. Loki and LogQL, where only labels are indexed, so cardinality rules apply to logs too ([Loki query docs](https://github.com/grafana/loki/blob/main/docs/sources/query/_index.md)).
8. Tempo, Pyroscope and Alloy, the OpenTelemetry Collector distribution ([Alloy](https://github.com/grafana/alloy)).
9. Dashboards as code.

**Grafana 13.3.0 (27 October 2026) is current**, and the image story changed. **`grafana/grafana-oss` stopped updating at 12.4.0**; use `grafana/grafana` or the free `grafana/grafana-enterprise`, which Grafana recommends ([Grafana Docker install](https://github.com/grafana/grafana/blob/main/docs/sources/setup-grafana/installation/docker/index.md)). Grafana 12.0 removed Angular plugins ([what's new in 12.0](https://github.com/grafana/grafana/blob/main/docs/sources/whatsnew/whats-new-in-v12/whats-new-in-v12-0.md)). 13.0 removed the `grafana-cli` and `grafana-server` binaries and made Git Sync and dynamic dashboards GA ([upgrade to v13.0](https://github.com/grafana/grafana/blob/main/docs/sources/upgrade-guide/upgrade-v13/upgrade-v13.0/index.md)). Grizzly and grafanactl are deprecated in favour of the new `gcx` CLI ([gcx](https://github.com/grafana/gcx); [grafanactl](https://github.com/grafana/grafanactl)). The as-code options are now Git Sync, Terraform, Ansible, the Grafana Operator and the typed Foundation SDK ([Grafana as code](https://github.com/grafana/grafana/blob/main/docs/sources/as-code/_index.md)). The Grafana Cloud free tier is quoted in search snippets as 10k active series, 50 GB of logs, 50 GB of traces and 14-day retention ([Grafana pricing](https://grafana.com/pricing/?pg=pricing)). Grafana's own page could not be opened to confirm this.

The fastest laptop tour of all four signals is the single **`grafana/otel-lgtm`** container. It bundles an OpenTelemetry Collector, Prometheus, Tempo, Loki, Pyroscope and Grafana, takes OTLP on 4317 and 4318, and is explicitly for development and demos only ([docker-otel-lgtm](https://github.com/grafana/docker-otel-lgtm)). Other good labs: provision the RED dashboard from files and diff it against a UI-built export; cut a deliberately bloated 40-panel dashboard down to six panels that answer one question; run the official Loki quickstart Compose stack and write five LogQL queries of increasing difficulty ([Loki quickstart](https://grafana.com/docs/loki/latest/get-started/quick-start/tutorial/)).

### ELK/EFK: an index is the back of a book, and shards cannot be resized

Logging works best taught in this order:

1. **Why centralize.** On Kubernetes the log agent must run on every node, which is why Fluent Bit ships as a DaemonSet ([Fluent Bit on Kubernetes](https://github.com/fluent/fluent-bit-docs/blob/master/installation/downloads/kubernetes.md)).
2. **Logs as structured events.**
3. **The pipeline**: ship, parse, store and index, search.
4. **Elasticsearch internals.** A document is a JSON row. An index is a named collection. A mapping is a schema inferred from the first document, which then sticks ([Elastic index basics](https://github.com/elastic/docs-content/blob/main/manage-data/data-store/index-basics.md)). Lucene segments are inverted indexes, searchable within about one second ([near real-time search](https://github.com/elastic/docs-content/blob/main/manage-data/data-store/near-real-time-search.md)). **The primary shard count is fixed at index creation, while replicas can change at any time** ([clusters, nodes and shards](https://github.com/elastic/docs-content/blob/main/deploy-manage/distributed-architecture/clusters-nodes-shards.md)).
5. **The shippers.** Fluent Bit uses about 450 KB of memory against Fluentd's 60 MB or more ([Fluentd and Fluent Bit](https://github.com/fluent/fluent-bit-docs/blob/master/about/fluentd-and-fluent-bit.md)).
6. **Kibana Discover**, with KQL in "classic" mode and the piped ES|QL ([Kibana Discover](https://github.com/elastic/docs-content/blob/main/explore-analyze/discover.md)).
7. **Lifecycle and cost**: index templates, data streams, ILM and retention.
8. **The licence history.** Elastic moved to ELv2/SSPL in 2021, AWS forked OpenSearch, and in August 2024 Elastic **added** AGPLv3 as a third option rather than replacing the others ([Elasticsearch LICENSE](https://github.com/elastic/elasticsearch/blob/main/LICENSE.txt); [BusinessWire](https://www.businesswire.com/news/home/20240829537786/en/Elastic-Announces-Open-Source-License-Elasticsearch-Kibana)).

Current versions are newer than many briefs assume. **Elasticsearch and Kibana are at 9.5.5, and Fluent Bit is at 5.1.5, not 4.x.** In 9.x, new `logs-*-*` data streams default to the logsdb index mode, which in Elastic's benchmarks cut storage by up to 60% at a 10–20% indexing cost ([logs data streams](https://github.com/elastic/docs-content/blob/main/manage-data/data-store/data-streams/logs-data-stream.md)). OpenSearch 3.0 went GA in May 2025 under the Linux Foundation ([OpenSearch 3.0](https://opensearch.org/blog/unveiling-opensearch-3-0/)). The six classic mistakes are all documented:

- **Unstructured logs.**
- **Logging secrets.** OWASP lists session IDs, tokens, passwords, connection strings and PII as things to remove, mask or hash ([OWASP Logging Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Logging_Cheat_Sheet.md)).
- **Keeping logs forever** instead of using ILM delete phases ([ILM](https://github.com/elastic/docs-content/blob/main/manage-data/lifecycle/index-lifecycle-management.md)).
- **Mapping explosions**, which "can cause out of memory errors" ([mapping](https://github.com/elastic/docs-content/blob/main/manage-data/data-store/mapping.md)).
- **Oversharding.** Aim for 10–50 GB shards ([size your shards](https://github.com/elastic/docs-content/blob/main/deploy-manage/production-guidance/optimize-performance/size-shards.md)).
- **Tracing every request**, covered in the tracing section below.

The 2026 configuration traps:

- Fluent Bit's `suppress_type_name` must be `on` for Elasticsearch 8 and 9, or bulk requests fail on `_type` ([Fluent Bit Elasticsearch output](https://github.com/fluent/fluent-bit-docs/blob/master/pipeline/outputs/elasticsearch.md)).
- `Retry_Limit False` retries forever.
- With Docker's `fluentd` logging driver, **a container stops immediately if the collector is down**, unless `fluentd-async` is set ([Docker fluentd driver](https://github.com/docker/docs/blob/main/content/manuals/engine/logging/drivers/fluentd.md)).

For the Mac lab, Docker Desktop keeps container log files inside its VM. Feed Fluent Bit's `forward` input on port 24224 from that logging driver, rather than tailing files. Allocate at least 4 GB to Docker Desktop, and 6–8 GB if the tracing lab runs alongside ([Elastic Docker install](https://github.com/elastic/docs-content/blob/main/deploy-manage/deploy/self-managed/install-elasticsearch-docker-basic.md)). Elastic's `start-local` script is the official one-liner for a local Elasticsearch and Kibana. Its trial licence reverts to the free Basic tier after a month ([start-local](https://github.com/elastic/start-local/blob/main/README.md)). The most memorable demos:

- Create an index with one replica on one node and watch the cluster go yellow, then set replicas to 0 and watch it go green.
- Run `_analyze` to see the back-of-book tokens.
- Send `"status":"200"` and later `"status":200` to a fresh index to watch dynamic mapping go wrong.
- Answer "errors per service in the last 15 minutes" in both KQL and ES|QL.

Close with Loki as the cost contrast: it indexes only labels and keeps compressed chunks in object storage, so it is cheaper but has no full-text index ([Loki overview](https://github.com/grafana/loki/blob/main/docs/sources/get-started/overview.md)).

### OpenTelemetry: one tracking number, sampled on purpose

Tracing works best taught in this order:

1. **Why traces.**
2. **The span**: a labelled stopwatch with attributes, events, links, a status and a kind ([OTel traces](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/concepts/signals/traces.md)).
3. **The trace**: a tree of spans sharing one `trace_id`, like a parcel's tracking history.
4. **Context propagation** through the W3C `traceparent` header, formatted `00-<32-hex trace-id>-<16-hex parent-id>-<flags>` ([W3C trace-context header](https://github.com/w3c/trace-context/blob/main/spec/20-http_request_header_format.md); [OTel context propagation](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/concepts/context-propagation/index.md)).
5. **Sampling.** Head sampling keeps whole traces by trace-ID ratio but cannot guarantee that error traces are kept. Tail sampling decides after the spans arrive ([OTel sampling](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/concepts/sampling/index.md)).
6. **The project itself**: API vs SDK, zero-code vs manual instrumentation ([OTel Python getting started](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/languages/python/getting-started.md)), OTLP on 4317 (gRPC) and 4318 (HTTP), and the Collector's receivers → processors → exporters pipelines ([Collector configuration](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/collector/configuration.md)).
7. **Backends.**

The intuition that keeps learners oriented: **OpenTelemetry is the plumbing, not the store**. Jaeger, Tempo, Elastic or Dynatrace hold and display the data.

Three 2025–26 changes break most older material:

- **Collector v0.144.0 renamed the `otlp` exporter to `otlp_grpc` and `otlphttp` to `otlp_http`.** The old names survive only as deprecated aliases, and current docs batch through the exporter's `sending_queue` ([Collector CHANGELOG](https://github.com/open-telemetry/opentelemetry-collector/blob/main/CHANGELOG.md)). The Collector is at v0.164.0.
- **Jaeger v1 reached end of life.** v2 is built on the OpenTelemetry Collector, the Jaeger client libraries are retired in favour of OTel SDKs, and you send it OTLP ([CNCF: Jaeger at 10](https://cncf.io/blog/2025/09/01/jaeger-at-10-forged-in-community-reborn-in-opentelemetry)). Jaeger 2.22.0 runs as an all-in-one container on `localhost:16686` with in-memory storage ([Jaeger v2 getting started](https://github.com/jaegertracing/documentation/blob/main/content/docs/v2/_dev/getting-started.md)).
- **Tempo 3.0 (May 2026) re-architected around separate read and write paths**, dropped triple replication, and made TraceQL metrics GA ([Tempo 3.0 release notes](https://github.com/grafana/tempo/blob/main/docs/sources/tempo/release-notes/v3-0.md)).

The beginner mistakes:

- **Leaving the SDK's default sampler, `parentbased_always_on` (100%), in production** ([OTel SDK configuration](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/languages/sdk-configuration/general.md)). The sampling docs note that 1% or less often represents high-volume traffic accurately.
- Expecting head sampling to catch errors.
- Installing the retired Jaeger client.
- Running Flask's debug reloader, which breaks instrumentation; use `use_reloader=False` ([OTel zero-code Python example](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/zero-code/python/example.md)).
- Treating Jaeger all-in-one as persistent.
- Copying pre-2026 Collector configs.
- Putting PII in span attributes instead of hashing or deleting it in the Collector's `attributes` processor.

The free lab runs a Flask app under `opentelemetry-instrument` with `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317`, sending to Jaeger. Its most valuable step adds a second service, so one trace spans two processes and the printed `traceparent` matches the trace ID in Jaeger. Stretch steps:

- Set `OTEL_TRACES_SAMPLER=parentbased_traceidratio` at 0.1 and count the traces that arrive.
- Compare head sampling with Collector tail sampling that keeps every error.
- Enable Python log auto-instrumentation so log lines carry `otelTraceID` and can be found in Kibana ([OTel Python logs example](https://github.com/open-telemetry/opentelemetry.io/blob/main/content/en/docs/zero-code/python/logs-example.md)). This ties the logging and tracing lessons together.

### Dynatrace: one agent, a self-drawing map, and a query bill

Dynatrace is the commercial counterpoint, best taught as "agent-first, auto-discovered, causal". Concepts in order:

1. The problem: signals scattered across tools.
2. SaaS vs Managed. Grail, AppEngine and AutomationEngine are SaaS-only ([Unavailable in Dynatrace Managed](https://docs.dynatrace.com/managed/upgrade/unavailable-in-managed)).
3. **OneAgent**, which instruments every process on a host without code changes.
4. ActiveGate, the routing and proxy component.
5. Entities.
6. **Smartscape**, a live dependency graph that nobody draws by hand.
7. **PurePath**, per-request code-level traces ([PurePath docs](https://docs.dynatrace.com/docs/observe-and-explore/purepath-distributed-traces)).
8. **Davis root-cause analysis**, which "does not rely only on time correlation". It follows trace dependencies and runs a fault-tree analysis to the most probable root cause, producing one problem instead of forty alerts ([root cause analysis](https://docs.dynatrace.com/docs/shortlink/next-gen-ai-analytics)).

The practice lesson then gets a tenant, gets data in through the Operator or OTLP, and climbs a DQL ladder: `fetch` → `filter` → `summarize` → `makeTimeseries`. It turns those queries into SLOs and a Site Reliability Guardian release check triggered from CI/CD ([release validation](https://docs.dynatrace.com/docs/deliver/quality-gates)), and closes with cost. Contrast this with assembling Prometheus, Grafana, Loki and Tempo yourself: free software, but four or five backends to run and correlation to build by hand. Dynatrace, Datadog, New Relic, Grafana Labs and Elastic were all Leaders in Gartner's 2025 Magic Quadrant, and Dynatrace says it placed highest for execution ([Dynatrace press release](https://www.businesswire.com/news/home/20250710820419/en/Dynatrace-Positioned-Highest-in-Execution-in-the-2025-Gartner-Magic-Quadrant-for-Observability-Platforms)). That is a vendor claim.

The names changed in 2026, so learners will see both sets. **At Perform 2026 (28 January 2026) Dynatrace grouped its AI under "Dynatrace Intelligence".** Davis is now the root-cause component inside it, **Dynatrace Assist succeeds Davis CoPilot**, and agentic workflows with approvals plus an MCP server are the focus ([Perform 2026 press release](https://www.dynatrace.com/news/press-release/perform-2026-ignites-new-era/); [Techzine](https://www.techzine.eu/blogs/infrastructure/144561/dynatrace-intelligence-aims-for-autonomous-operations/); [Dynatrace Assist](https://www.dynatrace.com/news/blog/dynatrace-assist-ask-analyze-and-act-with-dynatrace-intelligence/)). APIs still use `davis-copilot:*` scopes. The local open-source MCP server is deprecated in favour of `dtctl` and a remote MCP server ([dynatrace-mcp](https://github.com/dynatrace-oss/dynatrace-mcp); [dtctl](https://github.com/dynatrace-oss/dtctl)). "Latest Dynatrace" apps at `<env>.apps.dynatrace.com` sit alongside "classic apps", and some classic features have no direct replacement yet ([capability mapping](https://docs.dynatrace.com/docs/platform/upgrade/foundations/capability-mapping-classic-to-latest)). In DQL, `dt.entity.*` fields are deprecated in favour of `dt.smartscape.*` ([Dynatrace for AI skills](https://github.com/Dynatrace/dynatrace-for-ai)).

Dynatrace's own DQL skill lists the beginner traps, and most fail **silently with zero rows**:

- DQL is a left-to-right pipeline, not SQL; equality is `==`.
- Group-by lists need braces (`by: {severity}`).
- The log level field is `loglevel` and the message is `content`.
- Metrics come from `timeseries`, not `fetch`.
- You must alias an aggregate before sorting on it.
- Wrapping a filtered field in `lower()` "defeats the Grail index" ([dt-dql-essentials](https://github.com/Dynatrace/dynatrace-for-ai)).

The other traps are conceptual. Learners assume auto-instrumentation removes the need to define SLOs. They forget that under the Dynatrace Platform Subscription ingest, retention **and query scanning** are all metered, so MCP-triggered queries "may incur costs" by gigabytes scanned ([dynatrace-mcp README](https://github.com/dynatrace-oss/dynatrace-mcp); [how pricing works](https://docs.dynatrace.com/docs/license/how-pricing-works)). And they follow Classic screenshots, or use `live.` URLs where `apps.` URLs belong.

The free path for an Apple Silicon learner has three steps:

1. **The public Playground**: sample data and nothing to install ([Dynatrace get started](https://docs.dynatrace.com/docs/discover-dynatrace/get-started)). Use it for the DQL ladder, deliberately running SQL-style mistakes to read the errors.
2. **The 15-day trial plus the official obslab "Release Validation" lab**, which runs the OpenTelemetry demo in GitHub Codespaces ([obslab-release-validation](https://github.com/Dynatrace/obslab-release-validation)). This sidesteps arm64 entirely. Turning on the `paymentServiceFailure` feature flag makes the guardian fail the release.
3. **A best-effort Operator install on local kind.** Operator images are multi-arch, and Dynatrace runs its own end-to-end tests on kind ([Dynatrace Operator](https://github.com/Dynatrace/dynatrace-operator)), but no official statement supports kind or arm64 Macs. The official sample ActiveGate also requests 6 GiB of memory ([cloudNativeFullStack sample](https://github.com/Dynatrace/dynatrace-operator/blob/main/assets/samples/dynakube/v1beta6/cloudNativeFullStack.yaml)). Start with `applicationMonitoring` and a smaller ActiveGate.

## Security and platforms: generate, then verify

### The software supply chain: ingredient list, recall check, seal, delivery note

Teach the supply chain as a sequence, with an analogy and a command for each step:

1. **An SBOM is the ingredient list.** `syft <image>` writes SPDX and CycloneDX in one run ([syft](https://github.com/anchore/syft/blob/main/README.md)).
2. **Scanning checks that list against recall notices.** grype can rescan a stored SBOM later, without the image ([grype](https://github.com/anchore/grype/blob/main/README.md)). Trivy adds secret and IaC scanners ([trivy](https://github.com/aquasecurity/trivy/blob/main/README.md)).
3. **Signing is a tamper-evident seal.** Cosign's default keyless flow exchanges an OIDC login for a short-lived Fulcio certificate and records the signature in the public Rekor log, where it "cannot be removed later" ([cosign](https://github.com/sigstore/cosign/blob/main/README.md)).
4. **Provenance is a signed delivery note** naming the repo, commit, workflow and builder. SLSA's build levels climb from "provenance exists" (L1) to "signed by a hosted platform" (L2) to "hardened build platform" (L3) ([SLSA build track](https://github.com/slsa-framework/slsa/blob/main/spec/build-track-basics.md)).
5. **Verification is the step people skip.** GitHub itself warns that "generating attestations alone doesn't provide any security benefit" ([GitHub artifact attestations](https://github.com/github/docs/blob/main/content/actions/concepts/security/artifact-attestations.md)).

Anchor the lesson in three incidents, each of which hit a link other than the application's own code:

- **The xz-utils backdoor (CVE-2024-3094)**, planted in releases 5.6.0 and 5.6.1 by a contributor who spent years earning maintainer trust ([Datadog Security Labs](https://securitylabs.datadoghq.com/articles/xz-backdoor-cve-2024-3094/)).
- **tj-actions/changed-files (CVE-2025-30066)**, whose repointed tags dumped CI secrets ([CISA](https://www.cisa.gov/news-events/alerts/2025/03/18/supply-chain-compromise-third-party-github-action-cve-2025-30066)).
- **The Trivy compromise (CVE-2026-33634).** On 19 March 2026, attackers using credentials that had not been fully rotated published a malicious Trivy v0.69.4 and rewrote 75 of 76 `trivy-action` tags, **turning a security scanner into the attack tool** ([Endor Labs](https://www.endorlabs.com/vulnerability/cve-2026-33634); [Wiz](https://wiz.io/blog/trivy-compromised-teampcp-supply-chain-attack)).

The current tools are syft v1.55.0, grype v0.121.0, trivy v0.76.1 and cosign v3.1.4. **Cosign v3 made the standardized bundle format and OCI 1.1 referrers the default** ([Cosign 3.0](https://blog.sigstore.dev/cosign-3-0-available/)). **SLSA v1.2 added a Source Track** ([SLSA v1.2 what's new](https://github.com/slsa-framework/slsa/blob/releases/v1.2/spec/whats-new.md)). GitHub's docs now use **`actions/attest@v4`**, which supersedes the older `attest-build-provenance` name. Attestations on their own reach SLSA Build Level 2, and building inside a shared reusable workflow reaches Level 3 ([use artifact attestations](https://github.com/github/docs/blob/main/content/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations.md); [SLSA Build Level 3 guide](https://docs.github.com/actions/security-guides/using-artifact-attestations-and-reusable-workflows-to-achieve-slsa-v1-build-level-3)).

The misconceptions are one-time actions mistaken for ongoing controls. Scanning once misses CVEs published after you ship, as xz showed. Signing is not the same as being safe. Generating attestations without verifying them adds nothing. Signing `:latest` instead of a digest signs a moving target. Every lab is free:

- Generate SBOMs for the course image.
- Compare grype and trivy counts as the base image changes.
- Sign a tarball keylessly with cosign, flip one byte, and watch `verify-blob` fail.
- Add `actions/attest@v4` in a public repo and run `gh attestation verify` locally.
- Rewrite every `uses:` line to a full SHA.

### Secrets, access and policy: base64 is an alphabet, not a lock

Order this lesson to follow the secret's journey:

1. **Kubernetes Secrets are stored unencrypted in etcd.** Anyone who can create a Pod in a namespace can read every Secret there, and base64 is "obscured but not secret" ([Kubernetes Secrets](https://github.com/kubernetes/website/blob/main/content/en/docs/concepts/configuration/secret.md)).
2. **Keep secrets out of Git.** gitleaks scans *history*, because deleting a secret in a later commit leaves it in earlier ones ([gitleaks](https://github.com/gitleaks/gitleaks/blob/master/README.md)). GitHub's push protection for users is on by default, but repository-level protection is off by default and can be bypassed with a reason ([push protection](https://github.com/github/docs/blob/main/content/code-security/concepts/secret-security/push-protection.md)).
3. **Where real secrets live.** HashiCorp Vault remains under the Business Source License, now with IBM as licensor; 2.0.0 shipped on 14 April 2026 ([Vault LICENSE](https://github.com/hashicorp/vault/blob/main/LICENSE); [Vault CHANGELOG](https://github.com/hashicorp/vault/blob/main/CHANGELOG.md)). OpenBao is the MPL-2.0 fork, hosted by the OpenSSF ([OpenBao](https://github.com/openbao/openbao/blob/main/README.md)).
4. **How secrets reach the cluster.** The External Secrets Operator syncs from a store; it is now at v2.x and ships a `fake` provider that suits laptop practice ([ESO fake provider](https://github.com/external-secrets/external-secrets/blob/main/docs/provider/fake.md)). Sealed Secrets encrypts with a controller key, like a one-way mailbox slot ([Sealed Secrets](https://github.com/bitnami-labs/sealed-secrets/blob/main/README.md)). SOPS encrypts values with age or a cloud KMS ([SOPS](https://github.com/getsops/sops/blob/main/README.rst)).
5. **RBAC.** Avoid wildcards, which "also" grant future resource types, and avoid `cluster-admin` ([RBAC good practices](https://github.com/kubernetes/website/blob/main/content/en/docs/concepts/security/rbac-good-practices.md)).
6. **Admission control and policy as code.** Kyverno and Gatekeeper complement RBAC rather than replacing it ([Kyverno README](https://github.com/kyverno/kyverno/blob/main/README.md)).

The policy-engine landscape shifted in 2026. **Kyverno graduated from the CNCF on 24 March 2026** ([CNCF announcement](https://www.cncf.io/announcements/2026/03/24/cloud-native-computing-foundation-announces-kyvernos-graduation/)), and **Kyverno 1.19 (20 August 2026) deprecated `ClusterPolicy`, `Policy` and the cleanup policies, with removal planned for 1.20, estimated for November 2026** ([Kyverno 1.19 release](https://github.com/kyverno/website/blob/main/src/content/blog/announcing-kyverno-release-1.19/index.md)). Teach the CEL-based `ValidatingPolicy` from the official quick start instead ([Kyverno quick start](https://github.com/kyverno/website/blob/main/src/content/docs/docs/introduction/quick-start.md)), and mention Gatekeeper's Rego as the main alternative ([Gatekeeper](https://github.com/open-policy-agent/gatekeeper/blob/master/README.md)). Any 2024 Kyverno tutorial built on `kind: ClusterPolicy` will soon stop working. The free labs:

- Decode a Secret with `base64 -d`.
- Show that a Pod-creating user can read Secrets they cannot `get`.
- Block a planted fake key with gitleaks' pre-commit hook.
- Get one database password into kind three ways (ESO fake provider, Sealed Secrets, SOPS with age) and ask which file is safe to commit in each.
- Check a namespaced Role with `kubectl auth can-i`.
- Deny a Deployment that lacks a `team` label with a `ValidatingPolicy`. The browser playground at [playground.kyverno.io](https://playground.kyverno.io/) needs no cluster at all.

### Platform engineering, FinOps and AI: same guardrails, new actor

Platform engineering's consensus is that **a platform is an internal product that developers choose, not one they are ordered onto**. The CNCF maturity model scores five aspects (investment, adoption, interfaces, operations, measurement) across four levels, from Provisional to Optimizing. It calls mandated adoption "extrinsic push" and treats "intrinsic pull", backed by feedback and roadmaps, as the more mature level ([CNCF platform maturity model](https://github.com/cncf/tag-app-delivery/blob/main/platforms-maturity-model/v1/index.md); [CNCF Platforms White Paper](https://tag-app-delivery.cncf.io/whitepapers/platforms/)). A September 2026 CNCF post adds that many teams stall at level two on interfaces, and each aspect is scored separately, so you need not aim for level four everywhere ([CNCF blog](https://www.cncf.io/blog/2026/09/01/platform-engineering-maturity-from-toolchain-to-self-service/); [heise](https://heise.de/-10397214)). Golden paths are "paved roads" of templates and docs that make the compliant way the easy way, not the only way. Backstage, now v1.56.2 and still CNCF-incubating, is "a framework for building developer portals". It is the shop front, not the shop ([Backstage](https://github.com/backstage/backstage/blob/master/README.md)).

FinOps keeps its Inform → Optimize → Operate phases ([FinOps lifecycle](https://www.finops.org/framework/lifecycle/)). It extended its scope beyond public cloud with "Scopes", and a March 2026 refresh added an "Executive Strategy Alignment" capability ([FinOps Framework 2026](https://www.finops.org/insights/2026-finops-framework/)). For AI, the DORA 2025 report surveyed nearly 5,000 practitioners, found about 90% AI adoption, and framed AI as **"an amplifier"** of a team's existing strengths and dysfunctions ([Google Cloud: 2025 DORA report](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report); [DORA AI research](https://www.dora.dev/research/ai)). GitHub's agent docs say "you remain responsible for... reviewing the agent's work" ([GitHub Copilot agents](https://github.com/github/docs/blob/main/content/copilot/concepts/agent-capabilities/about-agents/about-github-copilot-agents.md)). Its Agentic Workflows run in firewalled containers with read-only tokens by default ([GitHub Agentic Workflows](https://github.com/github/docs/blob/main/content/copilot/concepts/agent-capabilities/agent-powered-workflows-and-operations/about-github-agentic-workflows.md)). The official MCP servers default to safety: GitHub's offers `--read-only` ([github-mcp-server](https://github.com/github/github-mcp-server/blob/main/README.md)), and Terraform's keeps approval-requiring tools off unless `ENABLE_TF_OPERATIONS=true` ([terraform-mcp-server](https://github.com/hashicorp/terraform-mcp-server/blob/main/README.md)). A read-only flag does not shrink the credentials a server inherits, though, so RBAC still matters ([kubernetes-mcp-server](https://github.com/containers/kubernetes-mcp-server/blob/main/README.md); [Tailscale on Kubernetes MCP](https://tailscale.com/learn/kubernetes-mcp)).

The misconceptions here are tools mistaken for outcomes: "platform engineering = installing Backstage", "FinOps = cost cutting", "AI will fix a weak delivery process". The labs:

- Score your own setup on the maturity table.
- Turn `hello-devops` into a golden-path template whose manifests pass the Kyverno policy.
- Do FinOps "Inform" on kind by totalling CPU requests per `team` label.
- Run the Kubernetes MCP server read-only under a ServiceAccount bound to the `view` role, and confirm the assistant can read but cannot delete.

### The capstone doubles as certification practice

A strong capstone takes one service through the whole secure path:

1. Gitleaks plus push protection.
2. SHA-pinned, least-privilege CI.
3. SBOM, scan, keyless signature and `actions/attest@v4` provenance, all verified.
4. A Kyverno-checked deploy.
5. Secrets from ESO, Sealed Secrets or SOPS.
6. A namespaced ServiceAccount with no wildcards.
7. `team` labels for cost allocation.
8. Read-only AI helpers.

That checklist maps directly onto the exams. The CKA curriculum is 30% troubleshooting ([CKA curriculum](https://github.com/cncf/curriculum/blob/master/cka/README.md)), and the CKS gives 20% to supply-chain security, including SBOMs and signing ([CKS curriculum](https://github.com/cncf/curriculum/blob/master/cks/README.md)). CKA and CKAD curricula now track Kubernetes v1.37 ([cncf/curriculum](https://github.com/cncf/curriculum)). A sensible sequence is KCNA, then CKAD, then CKA, then KCSA or CKS, which requires a valid CKA ([SFEIR on CKS](https://institute.sfeir.com/en/kubernetes-training/cost-certification-cks/)). Third-party pages quote list prices of about US$250 for the multiple-choice KCNA ([open-exam-prep](https://open-exam-prep.com/blog/kubernetes-cloud-native-associate-kcna-exam-guide-2026)) and US$445 for the two-hour, hands-on CKA and CKAD, with frequent discounts ([SFEIR](https://institute.sfeir.com/en/kubernetes-training/cost-certification-cka/)). The Linux Foundation's pages could not be checked. In parallel, HashiCorp's **Terraform Associate (004)** is a one-hour exam at US$70.50 ([HashiCorp certifications](https://developer.hashicorp.com/certifications/infrastructure-automation)). Specialist options include the Prometheus PCA, the platform-engineering CNPA and CNPE, and the Backstage CBA. GitHub also offers an Actions certification ([GitHub certifications](https://github.com/github/docs/blob/main/content/get-started/showcase-your-expertise-with-github-certifications/about-github-certifications.md)). No official current format or price was found for the Dynatrace Associate exam.

## Conclusion

Learning DevOps in late 2026 turns out to be less about memorising fourteen tools than about two transferable reflexes. The first: ask what the declared desired state is and which loop reconciles it. The second: ask whether you are trusting a name or a hash. Once those are in place, Terraform's `moved` block, Argo CD's self-heal, a SHA-pinned action, a digest-signed image and a Gradle lockfile stop being separate trivia and become the same idea in different clothes. For a Kotlin/JVM engineer the asymmetry is clear. Gradle and the JVM's process model are already familiar, so the highest-return investment is the shell, networking and Linux processes, where the hidden expansion step and the 0.0.0.0-versus-127.0.0.1 confusion cause most early failures. The meta-skill worth teaching explicitly is dating a tutorial. Treat any of the following as an immediate warning sign that the material is outdated: `version:` in a Compose file, `dynamodb_table`, `kind: ClusterPolicy`, `grafana/grafana-oss`, `exporters: otlp:`, `jcenter()`, `--atomic`, or a plain `kubectl apply` of Argo CD.

Several dated changes land in the next few months, so material written today should name them. GitHub plans to enforce the `pull_request_target` default policy on 2 December 2026, though press reports said 2 November. Kyverno's removal of `ClusterPolicy` is estimated for November 2026. Helm 3 security fixes end on 10 February 2027, the same day Let's Encrypt moves to 64-day certificates. Gradle 10 aims to make the configuration cache the default, with no date announced. Four uncertainties remain:

- Most video channel attributions and all certification prices except Terraform's come from search snippets or third parties.
- The Grafana Cloud free-tier numbers and Dynatrace's trial terms could not be confirmed on the vendors' own pages.
- Running the Dynatrace Operator on kind on an arm64 Mac has no official support statement.
- The labs quoted here were validated on Linux sandboxes, not on an Apple Silicon Mac, so Mac-specific output wording should be checked once on real hardware before it is published.
